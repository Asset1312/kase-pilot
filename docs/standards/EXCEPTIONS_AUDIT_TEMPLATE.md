## 3. Неиспользуемые исключения

Здесь «неиспользуемый» означает отсутствие `raise`, `except` или импорта за
пределами файла определения. Абстрактные родители отдельно отмечены как
структурные.

| Класс | Причина | Вывод |
|---|---|---|
| `KasePilotError` | Структурный корень иерархии | Оставить |
| `ConfigurationError` | Конфигурационная валидация ещё не реализована | Оставить до реализации конфигурации |
| `BrokerError` | Структурный родитель | Оставить |
| `SecuritySessionError` | `SecuritySession` пока является заготовкой | Оставить |
| `RateLimitError` | Сигнал rate limit ещё не подтверждён | Оставить зарезервированным, не бросать по предположению |
| `StorageError` | Структурный родитель будущего слоя хранения | Оставить |
| `DatabaseError` | Слой БД не реализован | Оставить до реализации хранилища |
| `DataIntegrityError` | Проверки целостности не реализованы | Оставить до реализации хранилища |

## 4. Возможное дублирование смыслов

| Класс A | Класс B | Пересечение | Разграничение |
|---|---|---|---|
| `ApiRequestError` | отсутствующий транспортный класс | Сейчас один класс покрывает HTTP/сеть и ненулевой код API | Транспортная ошибка означает отсутствие корректного API-ответа; API-ошибка означает полученный и разобранный отказ брокера |
| `ValidationError` | `DataIntegrityError` | Оба связаны с некорректными данными | `ValidationError` — входные данные или внешний ответ; `DataIntegrityError` — уже сохранённые данные и инварианты хранилища |
| `AuthenticationError` | `SecuritySessionError` | Оба относятся к доступу | Первый — базовая идентификация/подпись; второй — повышенная подтверждённая сессия |
| `ApiRequestError` | `RateLimitError` | Rate limit является отказом API или транспорта | `RateLimitError` нужен только после подтверждения способа распознавания и должен быть более узким классом |

## 5. Соответствие типам ошибок

| Категория ошибки | Текущий класс | Соответствует? | Комментарий |
|---|---|---|---|
| Авторизация | `AuthenticationError` | Частично | Класс уместен, но используемый маппинг кодов брокера ещё требует официальной верификации |
| Security session | `SecuritySessionError` | Да структурно | Реального использования пока нет |
| HTTP / сеть | `ApiRequestError` | Частично | Смешано с отказами уровня API |
| Ошибка уровня API | `ApiRequestError` | Частично | Название допустимо, но класс одновременно используется для транспорта |
| Валидация ответа | `ValidationError` | Да | Невалидный JSON, envelope и типы переводятся в доменное исключение |
| База данных | `DatabaseError` | Да структурно | Слой БД ещё не реализован |
| Целостность данных | `DataIntegrityError` | Да структурно | Использование отсутствует |

## 6. Риски текущей иерархии

| Риск | Описание | Серьёзность |
|---|---|---|
| Смешение уровней | `ApiRequestError` обозначает и HTTP/сетевую ошибку, и корректно полученный отказ API | Средняя |
| Неподтверждённая классификация | Коды `4`, `7`, `8`, `12` уже преобразуются в `AuthenticationError`, хотя источник ещё отмечен как требующий проверки | Высокая перед live-запросом |
| Неиспользуемые классы | Семь классов пока выполняют только архитектурную роль | Низкая на текущем этапе |
| Слишком общий `ValidationError` | В будущем может смешать ошибки входных параметров и внешнего ответа | Низкая сейчас, средняя при росте проекта |
| Отсутствие обработки тайм-аута | Явного тайм-аута пока нет; его будущая ошибка должна иметь определённую категорию | Средняя |

## 7. Рекомендация

**Вариант:** Расширить минимально, после подтверждения API-контракта.

**Обоснование:**

Текущая иерархия логична для раннего каркаса и не требует удаления
зарезервированных классов. Единственный уже проявившийся структурный дефект —
смешение транспортных отказов и ошибок уровня API в `ApiRequestError`.
Классификацию кодов авторизации и rate limit нельзя закреплять окончательно до
верификации официального контракта.

**Конкретные предложения:**

| Действие | Класс | Обоснование |
|---|---|---|
| Добавить | `TransportError(BrokerError)` | Отделить HTTP, DNS, timeout и недоступность сервера от ответа API |
| Оставить | `ApiRequestError` | Использовать только для подтверждённых отказов уровня API |
| Оставить | `AuthenticationError` | Класс корректен; пересмотреть только правила его вызова после верификации кодов |
| Оставить | `SecuritySessionError`, `RateLimitError` | Нужны архитектурно, но не должны использоваться по неподтверждённым признакам |
| Оставить | Ветка `StorageError` | Соответствует запланированному слою хранения |
| Рассмотреть позже | `ResponseValidationError` | Выделять из `ValidationError` только если появится практическая неоднозначность |

Изменения в коде по результатам аудита не вносились.
