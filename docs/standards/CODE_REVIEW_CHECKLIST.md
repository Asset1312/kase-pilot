# Чек-лист аудита Python API-клиента брокера

Внутренний стандарт KASE Pilot. Конкретные детали API брокера нельзя считать
требованием, пока они не подтверждены официальной документацией или
контролируемым live-тестом и не зафиксированы в `docs/API_NOTES.md`.

## 1. Архитектура

| Что проверить | Риск | Приемлемый результат |
|---|---|---|
| Один класс — одна ответственность | Класс-«бог» невозможно тестировать и расширять | Транспорт, авторизация, сессия и бизнес-логика находятся в разных классах |
| Брокерный код изолирован | Смена брокера требует переписать приложение | Брокерная интеграция находится в отдельном пакете |
| Нет циклических импортов | Ошибки импорта и сложная отладка | `python -c "import kase_pilot.broker"` проходит; при необходимости используются `import-linter` или Ruff |
| Публичный интерфейс минимален | Изменения ломают вызывающий код | Внутренние символы помечены `_`; `__all__` допустим, но не обязателен |
| Зависимости инжектируются | Компоненты нельзя подменить в тестах | Конструктор принимает транспорт, логгер и конфиг, когда они нужны |

## 2. HTTP-транспорт

| Что проверить | Риск | Приемлемый результат |
|---|---|---|
| Транспорт явно выбран и задокументирован | Неявные зависимости и уязвимости | Зависимость зафиксирована в `pyproject.toml` либо используется stdlib |
| Транспорт инжектируется | Тесты делают реальные запросы | Принимается callable или объект транспорта |
| Метод и `Content-Type` заданы явно | Сервер неверно интерпретирует запрос | HTTP-метод и тип содержимого указаны при сборке запроса |
| Base URL не зашит в бизнес-логике | Нельзя сменить окружение | URL передаётся через конфиг или конструктор |
| Ответ читается и ресурс закрывается | Утечки соединений | Используется context manager, тело читается один раз |

## 3. Авторизация

| Что проверить | Риск | Приемлемый результат |
|---|---|---|
| Учётные данные не хардкодятся | Утечка через репозиторий | Секреты поступают из защищённого конфига или окружения |
| Авторизация не выполняется при импорте | Побочные эффекты и сетевые вызовы на старте | Инициализация выполняется явно |
| Метод авторизации подтверждён | Запросы отклоняются или раскрывают секрет | Контракт подтверждён официальным источником |
| Секрет не передаётся вместо производного артефакта | Компрометация ключа | Секрет используется только согласно подтверждённому протоколу |

## 4. Security Session

| Что проверить | Риск | Приемлемый результат |
|---|---|---|
| Жизненный цикл управляется явно | Работа с истёкшей сессией | Сессия открывается, проверяется и закрывается явно |
| Критерий истечения подтверждён | Неверная проверка валидности | Поля и формат срока действия взяты из подтверждённого контракта |
| Подтверждение вынесено отдельно | Смешение ответственности | SMS/токен/иной механизм инжектируется |
| Сессия отделена от базовой авторизации | Сильная связанность | Используются отдельные компоненты |
| Нет неявного открытия | Неожиданные сообщения или операции | Открытие происходит только по явному вызову |

## 5. Обработка ошибок

| Что проверить | Риск | Приемлемый результат |
|---|---|---|
| HTTP- и API-ошибки разделены | Вызывающий код не различает причины | Используются разные доменные исключения |
| Неизвестные ошибки не проглатываются | Новая ошибка выглядит успехом | Неуспешный ответ вызывает исключение с безопасным контекстом |
| Маппинг основан на подтверждённом контракте | Неверная классификация | Коды и схема ответа сверены с источником |
| Нет голых `except` | Ошибки скрываются | Перехватываются конкретные типы; причина сохраняется через `raise ... from` |

## 6. Тайм-ауты и повторные запросы

| Что проверить | Риск | Приемлемый результат |
|---|---|---|
| Тайм-аут задан явно | Бесконечное ожидание | Значение настраивается и передаётся каждому запросу |
| Повторы разрешены только для безопасных операций | Дублирование торговой операции | Идемпотентность подтверждена до включения retry |
| Backoff и лимит попыток заданы | Флудинг брокера | Задержка растёт, число попыток ограничено |

## 7. Логирование

| Что проверить | Риск | Приемлемый результат |
|---|---|---|
| Используется `logging`, не `print` | Логи нельзя управляемо перенаправить | Все сообщения идут через `logging.getLogger` или обёртку |
| Уровни корректны | Важные события теряются | INFO: успех; WARNING: повтор; ERROR: неустранимая ошибка |
| В логах нет секретов | Утечка ключей и токенов | Проверен каждый вызов `logger.*` |
| Данных достаточно для отладки | Ошибку нельзя воспроизвести | Метод, безопасный URL, код ответа и задержка |
| Получение логгера без побочных эффектов | IO при импорте | Получение логгера не выполняет файловых или сетевых операций |

## 8. Защита секретов

| Что проверить | Риск | Приемлемый результат |
|---|---|---|
| Нет секретов в коде и истории | Утечка через Git | Поиск характерных паттернов ничего не находит |
| Нет секретов в `repr`/`str` | Объект случайно попадает в лог | Значения маскируются как `***` |
| Нет секретов в исключениях | Трассировка попадает в систему мониторинга | Сообщения содержат только безопасные коды и описания |
| Секреты не сериализуются для отладки | Дамп сохраняется на диск | Секретные объекты не передаются напрямую в JSON, форматирование или логгер |
| Заголовки логируются по whitelist | Авторизационный заголовок попадает в лог | Разрешены только заведомо безопасные имена |

## 9. Валидация данных

| Что проверить | Риск | Приемлемый результат |
|---|---|---|
| Обязательные поля проверяются до чтения | `KeyError` или неверная интерпретация | Проверяются наличие и тип полей подтверждённой схемы |
| `bool` не принимается за `int` | Ложный код результата | `bool` исключается отдельной проверкой |
| Неожиданная структура отклоняется | Мусор попадает в сервис или БД | Возникает `ValidationError` |
| Бизнес-валидация не живёт в транспорте | Нарушение SRP | Она выполняется в модели или сервисе |

## 10. JSON-декодирование

| Что проверить | Риск | Приемлемый результат |
|---|---|---|
| Ошибка декодирования перехватывается | Сырой `JSONDecodeError` выходит наружу | Возникает доменное исключение с понятным сообщением |
| Кодировка задана явно | Нестандартный ответ декодируется неверно | Используется UTF-8 либо charset из `Content-Type` |
| Тип после `json.loads` проверяется | `Any` используется без проверки | Верхний уровень проверяется через `isinstance` |
| Финансовые значения не теряют точность | Цена и сумма искажаются во `float` | Транспорт возвращает сырой `dict`, преобразование в `Decimal` делает модель или сервис |

## 11. Тестируемость

| Что проверить | Риск | Приемлемый результат |
|---|---|---|
| Транспорт и auth provider инжектируются | Тесты требуют сеть и ключ | Используются заглушки |
| Нет изменяемого глобального состояния | Тесты зависят от порядка | Каждый тест создаёт собственный объект |
| Конструктор не делает IO | Создание клиента требует сеть | IO начинается только по явному вызову |
| Тестируется публичный контракт | Рефакторинг ломает тесты | Проверки выполняются через публичные методы |

## 12. Unit-тесты

| Что проверить | Риск | Приемлемый результат |
|---|---|---|
| Покрыты ветви ошибок и невалидные ответы | Ошибки обнаруживаются в production | Есть параметризованные тесты подтверждённых вариантов |
| Проверено отсутствие вызова транспорта при локальной ошибке | Неверный запрос всё же уходит | Fake-транспорт фиксирует вызовы |
| Входные параметры не мутируются | Скрытый побочный эффект | Исходное значение сравнивается после вызова |
| Нет зависимости от реальной подписи | Хрупкие тесты | Auth-заглушка возвращает статичный безопасный вклад |

## 13. Интеграционные тесты

| Что проверить | Риск | Приемлемый результат |
|---|---|---|
| Отделены от unit-тестов | CI делает live-запросы | Отдельная папка или pytest-маркер |
| Требуют явного включения | Случайный запрос к брокеру | По умолчанию пропускаются |
| Среда подтверждена и безопасна | Операция на реальном счёте | Используется официально подтверждённый sandbox либо только согласованный read-only сценарий |
| Не зависят от состояния счёта | Нестабильность | Проверяются устойчивые read-only свойства |

## 14. WebSocket

| Что проверить | Риск | Приемлемый результат |
|---|---|---|
| Отделён от REST | Сильная связанность | Независимый компонент |
| Heartbeat и reconnect управляемы | Обрывы или флудинг | Интервалы и лимиты настраиваются |
| Авторизация подтверждена отдельно | Ошибочное переиспользование REST-схемы | Контракт WebSocket верифицирован официально |

## 15. Безопасность торговых операций

| Что проверить | Риск | Приемлемый результат |
|---|---|---|
| Write-операции соответствуют этапу проекта | Случайная сделка | Недоступные операции отсутствуют из публичного API |
| Изменяющие операции требуют явного согласия | Непреднамеренное действие | Команда и параметры подтверждаются до отправки |
| Ограничения задокументированы | Функцию считают безопасной ошибочно | Read/write-возможности перечислены явно |

## 16. Read-only режим

| Что проверить | Риск | Приемлемый результат |
|---|---|---|
| Все доступные команды действительно read-only | Скрытая мутация счёта | Семантика подтверждена документацией |
| HTTP-метод не принимается за семантику | POST ошибочно считается изменением | Read-only определяется командой, а не только методом |
| Кэш отсутствует либо управляется | Устаревшие данные | TTL и инвалидация заданы явно |

## 17. Идемпотентность

| Что проверить | Риск | Приемлемый результат |
|---|---|---|
| Идемпотентность подтверждена для каждой повторяемой команды | Дублирование операции | Retry включён только после классификации команды |
| Идентификатор запроса используется по контракту | Повтор не распознаётся сервером | Формат и назначение подтверждены; значения не выдуманы |

## 18. Rate limits

| Что проверить | Риск | Приемлемый результат |
|---|---|---|
| Лимиты задокументированы или помечены TBD | Блокировка клиента | Известные значения имеют источник |
| Превышение лимита различимо | Нельзя выбрать стратегию повтора | Используется отдельное исключение после подтверждения сигнала API |
| Нет плотных циклов запросов | Флудинг | Частота ограничивается явно |

## 19. Закрытие соединений

| Что проверить | Риск | Приемлемый результат |
|---|---|---|
| HTTP-ресурс закрывается и при ошибке | Утечка сокетов | Context manager или `finally` |
| WebSocket закрывается явно | Зависшие соединения | `close()` гарантирован |
| Security session закрывается | Накопление активных сессий | Явный `close()` или context manager |

## 20. Перед первым live-запросом

| Что проверить | Риск | Приемлемый результат |
|---|---|---|
| REST-авторизация подтверждена | Отклонение запроса или утечка | Есть официальный источник или контролируемая верификация |
| Идентификаторы и схема запроса подтверждены | Неверный payload | Все поля имеют зафиксированный источник |
| Безопасная тестовая среда проверена | Воздействие на живой счёт | Sandbox подтверждён официально; иначе сценарий строго read-only |
| Защита Git и логов проверена | Утечка при первом запуске | Сканирование секретов и ручная проверка DEBUG-логов пройдены |

## Неподтверждённые детали конкретного брокера

До верификации нельзя закреплять в коде или использовать как критерий
успешности:

- коды ошибок, включая `4`, `7`, `8`, `12`;
- имена полей ответа, включая `code`, `data`, `errMsg`;
- production- и sandbox-URL;
- алгоритм подписи;
- наличие, формат и семантику `nonce`;
- имена полей авторизационного payload;
- имя и расположение клиентского криптографического файла;
- поля срока действия security session;
- значения `safety_type_id`.
